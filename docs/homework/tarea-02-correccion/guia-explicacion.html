Guía para la defensa de la Tarea 2 (uso del profesor)

No se entrega a los alumnos.

Formato: en la semana 8, cada alumno defiende un ejercicio sorteado (1 a 4), en 3 o 4 minutos, con su código abierto en VS Code. Se recomienda:

  1. Una pregunta de explicación sobre una parte de su código.
  2. Una pregunta de predicción: dar una entrada y pedir los resultados antes de ejecutar.
  3. Un cambio en vivo pequeño, que debe compilar y funcionar.

Escala (va en explicacion de notas.csv):

Valor Criterio
1 Explica con seguridad, predice bien y hace el cambio.
0.75 Duda en algún detalle o necesita una pista pequeña.
0.5 Explica la idea general, pero no justifica ni logra el cambio.
0.25 Reconoce partes, pero no explica cómo funcionan.
0 No puede explicar su código.

Las predicciones de abajo se comprobaron con las soluciones de referencia. Cuando la respuesta depende de cómo lo programó el alumno (por ejemplo, la decoración), solo se piden los resultados con etiqueta.

Ejercicio 1: Ventas del día

Preguntas de explicación

  • ¿Qué variable es el contador y cuál el acumulador? ¿Con qué valor empiezan y por qué?
  • ¿Por qué se lee el primer monto antes del while y otra vez al final del cuerpo? (Lectura adelantada: la condición necesita un monto para evaluarse; si no, se procesaría el 0 como venta).
  • ¿Cómo evitas dividir entre cero? ¿Por qué total / ventas da 21 y no 21.2? (División entera; hace falta static_cast<double> o un double).
  • ¿Por qué el else if no necesita revisar monto >= 10? (Si se llegó ahí, la condición anterior fue falsa).

Predicciones

Entrada Resultados
0 Ventas 0, Total 0, Pequenas 0, Medianas 0, Grandes 0, Mayor 0, Promedio 0.00
49 50 10 9 0 Ventas 4, Total 118, Pequenas 1, Medianas 2, Grandes 1, Mayor 50, Promedio 29.50
40 45 5 0 Ventas 3, Total 90, Pequenas 1, Medianas 2, Grandes 0, Mayor 45, Promedio 30.00

Cambios en vivo

  • Que “grande” empiece en $40. Cambiar el límite en la condición de medianas (< 50 → < 40). Con 40 45 5 0 debe dar Medianas 0 y Grandes 2.
  • Agregar Menor:. La trampa: inicializarla en 0 hace que nunca cambie. Respuestas válidas: inicializarla con el primer monto (si no es 0), con un valor mayor que el máximo (10001), o con una bandera “primera venta”. Sin ventas debe imprimir 0. Con 49 50 10 9 0, Menor 9.
  • Pregunta: ¿qué pasa si se quita el if (ventas > 0) del promedio? (División 0/0: con double da nan o -nan; con int, error en ejecución).

Ejercicio 2: Juego de fichas

Preguntas de explicación

  • ¿Qué variable hace de conmutador y cómo cambia? (turno = 3 - turno, o un if).
  • ¿Qué variable hace de interruptor? ¿Dónde se enciende y cómo detiene el ciclo?
  • ¿Por qué el while tiene dos condiciones? ¿Qué pasaría con solo quedan > 0? (Después de una jugada inválida seguiría pidiendo jugadas).
  • ¿Cómo sabes quién ganó si hubo una jugada inválida? (El otro jugador: 3 - turno).
  • Si dibujan la mesa: ¿cuántas veces se repite el for interno en cada turno?

Predicciones

Entrada Resultados
7 3 3 1 Quedan 4, Quedan 1, Quedan 0, Ganador 1, Jugadas 3
6 2 2 3 Quedan 4, Quedan 2, Error: jugada invalida, Ganador 2, Jugadas 2
1 1 Quedan 0, Ganador 1, Jugadas 1

Cambios en vivo

  • Que pierda quien toma la última ficha. Al llegar a 0, el ganador es el otro jugador (3 - turno). Con 7 3 3 1: Ganador 2.
  • Permitir tomar hasta 4. Cambiar > 3 por > 4 en la validación (y el mensaje). Con 5 4 1: Quedan 1, Quedan 0, Ganador 2, Jugadas 2.
  • Que empiece el jugador 2. Inicializar turno = 2. Con 7 3 3 1: Ganador 2.

Ejercicio 3: Máquina expendedora

Preguntas de explicación

  • ¿Por qué el crédito se declara antes del do? (Si se declara dentro, vuelve a 0 en cada vuelta).
  • ¿Por qué do-while y no while? (El menú debe mostrarse al menos una vez; la opción se lee dentro).
  • ¿Qué pasa si se quita un break? (El programa sigue con el case siguiente. Por ejemplo, sin el break del case 1, después de insertar un billete también ejecuta la compra y lee un dato de más como producto).
  • ¿Por qué precio devuelve 0 para un producto que no existe? (Ningún producto cuesta 0, así que sirve de señal de “no existe” y main la revisa antes de comprar).
  • ¿Qué devuelve billeteValido(7) y cómo lo usa main?

Predicciones

Entrada Resultados
1 10 2 2 2 2 2 2 3 0 Credito 10, Entregado jugo, Credito 7, Entregado jugo, Credito 4, Entregado jugo, Credito 1, Devuelto 1, Vendidos 3, Recaudado 9
2 4 1 1 2 1 0 Error: producto invalido, Credito 1, Entregado agua, Credito 0, Vendidos 1, Recaudado 1
2 1 0 Error: credito insuficiente, Vendidos 0, Recaudado 0

Cambios en vivo

  • Agregar el producto 4 (por ejemplo, chocolate a $4). Un case 4 en precio y el nombre en el mensaje de entrega. Con 1 5 2 4 0: Credito 5, Entregado chocolate, Credito 1, Vendidos 1, Recaudado 4.
  • Aceptar billetes de $20. Solo cambia billeteValido. Con 1 20 3 0: Credito 20, Devuelto 20.
  • Que al apagar se devuelva el crédito. En el case 0, imprimir Devuelto: antes de Vendidos:.

Ejercicio 4: Analizador de números

Preguntas de explicación

  • Explica sumaDigitos paso a paso con n = 4528: ¿qué valen n % 10 y n / 10 en cada vuelta?
  • ¿Por qué esCapicua llama a invertir? (Reutiliza código: un número es capicúa si es igual a su invertido. Es la razón de tener funciones).
  • En esPrimo, ¿qué hace la bandera? ¿Por qué el 1 no es primo en tu código? ¿Hasta dónde busca divisores?
  • ¿Qué pasa con n = 0 en cada función? (El ciclo no se ejecuta: suma 0, invertido 0, capicúa SI, primo NO).

Predicciones

Pregunta Respuesta
invertir(500) 5
invertir(1210) y esCapicua(1210) 121; NO
Entrada 3 100 4 91 1 909 0 Capicua NO, Primo NO (91 = 7 × 13), Suma de digitos 18, Consultas 3

Cambios en vivo

  • Agregar la opción 5, Digitos: (cantidad de dígitos). Una función nueva y un case 5. La trampa: con n = 0 un while (n > 0) da 0, pero 0 tiene 1 dígito (se resuelve con do-while o un caso especial). Con 5 1200 5 0 0: Digitos 4, Digitos 1, Consultas 2.
  • Que Primo: imprima el menor divisor cuando no es primo. Más difícil; solo para quien termina rápido.
